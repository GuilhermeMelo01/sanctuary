
## Local Area Networks, including Hubs, Bridges, and Switches
#### HUB
![[Pasted image 20260530193456.png]]
A **Hub** is a way to connect many MAC address, but it has some problems:
1. Hub is dumb! It doesn't know the destination of the data.
	1. So, it sends the data to every MAC address in the domain.
2. If 2 Computers send the data at same time, it will cause a collision.

#### BRIDGE
![[Pasted image 20260530193831.png]]
The bridge came to answers some problems of the HUB.
1. The first thing is the Bridge separate the machines in two HUBS, so if I want to send a message from MAC1 to MAC2, It is going to send the message just to the half of the machines.
2. The L2 Bridge has half less collision than HUB.

#### SWITCH
![[Pasted image 20260530194204.png]]
Switch is even better than the Bridge, because each machine in the MAC TABLE has an address.
So, when the messages from MAC1 arrive in the switch, it knows exactly the destination of the message. 
The switch doesn't need to send the message to every machine in the domain.
A switch is a **broadcast domain**
Vantages of the switch:
1. Addresses to every machine in the domain.
2. Collision handler
3. The MAC1 can send the message to every machine in the broadcast domain.

**KICK REVIEW:**
- Unicast is a one-to-one communication
- Hubs are dumb
- Switches have MAC Tables
- L2 segment = broadcast domain
- Routers break up broadcast domains

## What Happens When a Computer Is Connected to a Switch?

![[Pasted image 20260531120445.png]]

So, every machine connected to the Ethernet Switch has a MAC address and a Port in the Switch MAC table.
In the example we have: MAC1 with the port 1.
A Switch can connect to another switch (or hub) through the address and port. 

**KICK REVIEW:**
- The MAC table associates MAC addresses with a port.
- Each entry in the MAC table maps a MAC address to a port.
- Multiple MAC addresses may be associated with a single port. 
- Entries in a MAC table are temporary 

## Layer 2 BUM Traffic: Broadcast, Unknown Unicast, Multicast
BUM Traffic stands for: 
**B  -> Broadcast**
**U  -> Unknown Unicast**
**M -> Multicast**

#### BROADCAST 

![[Pasted image 20260531121912.png]]

Let's say that I want to send a message for the MAC2 computer, but I just have the IP for this computer.
So, first I've to discover the MAC address of the the computer with IP2.
I will send a **ARP Request**.

**ARP** -> Address Resolution Protocol
**ARP Request:** Broadcast to discover the MAC associated with an API address.

**ARP Request Example:** Send a frame to the Switch, then the switch will send the frame to every computer in the networking asking who is using the IP2. The frame will get there and it is going to return the answer with the MAC address for that computer. 

#### Unknow Unicast

![[Pasted image 20260531152921.png]]

Unknown Unicast -> The switch does not know which port a MAC address is on.
So, If I want to send a message to MAC3 from the MAC1 they will be in different Switches, then the MAC1 must find the MAC3 when the Switch1 ask to Switch2.

## Layer 3: What are Routers?
![[Screenshot 2026-05-31 160638.png]]

Routers stays between segments (Broadcast) and are responsible to manage the frame between them.
So, If the computer inside of the Segment1 does a 'Broadcast', the routers knows that the segment2 is not part of the Segment1 and does not send the frame. 
The router has MAC address in the both sides of the segments.
